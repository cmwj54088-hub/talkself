# 自言：从 0.9.1 到 0.12.0 的完整更新

整理日期：2026-11-02。本文从 0.9.1 基线开始，按版本汇总其后全部已记录的产品改动及必要的项目整理；不是仅统计最近两天。

**当前最新本地候选版为 0.12.0。用户反馈：微信导入解析仍有问题，其他本轮功能正常，内层聊天可以打开。解析暂缓修复，不记为整体验收通过。**

## 0.9.1：基线与滚动定位修正

- 展开／收起项目待办栏时，尽量保持正在阅读的历史消息位置；原先在底部时保持底部。
- 用户主动滚动后交还控制，处理图片延迟加载及短视口下的位置变化。
- 保留原有微信聊天 ZIP 导入、文字／图文／视频／手写、全屏编辑、搜索、跨项目多目标转发及完整 JSON 备份。
- 原有首页左右滑动且底栏固定、项目待办栏仅显示未完成、长按菜单及文字／图文双击编辑继续保留，不作为后续版本首次新增功能重复计算。

当时微信聊天主要作为一条可编辑笔记保存；待办主要在待办栏和全局列表出现。这两处在后续版本重点改进。

## 0.10.0：离线体验、日期提醒与内容导出

### 输入、待办入口与首页

- 增加输入区展开及共享草稿处理，普通消息与待办切换保留内容；这一版的展开体验后来在 0.11.0 改为真正复用全屏编辑器。
- 简化模式切换按钮，明确笔记／待办模式及对应主操作；空内容禁用，修正按钮可见性。
- 精简待办行内重复的提醒按钮，保留编辑／菜单设置入口和提醒摘要。
- 首页使用三层深色灰度：顶栏／底栏最深、普通项目稍浅、置顶项目再浅。
- 双击底栏“项目”可定位带红色任务角标的项目，重复双击循环定位。

### 日期提醒

- 提醒可以指定日期和时间，独立于截止日期。
- 在用户明确授权后，增加应用内单次日期提醒及通知／精确闹钟／开机恢复相关权限，不增加联网权限。
- 完成、删除或清除提醒后取消应用内预约；重启后恢复未来预约。
- 系统时钟入口继续作为独立功能保留，不能传入指定年月日，也不能把保存偏好说成已经开启系统闹钟。

### 链接、筛选、花园与导出

- 识别 http/https 链接并显示离线生成的小卡片；点击弹外部浏览器选择器，由浏览器访问网页，返回自言继续记录。
- 自言不后台抓取网页标题／封面，不在笔记 WebView 内加载外部网站，不申请 INTERNET。
- 增加整个项目及分享预览的 Markdown 导出；有附件时输出包含 `.md` 和附件目录的 ZIP，正文使用相对引用。
- 全局待办增加单项目筛选，可与未完成／已完成／全部组合使用。
- 顶部统计卡片增加完成率花园：以花草树木繁密度表达已完成占总待办的比例；选择项目决定统计范围，状态筛选不改变分母，零任务显示空园。

## 0.10.1：布局、授权入口与花园体验修正

- 恢复连续排列的项目列表，去掉多余边缘／行间空隙，保留头像右侧淡细分隔线与三层灰度。
- 将通知、精确闹钟授权、通知声音渠道、预约数量及失败状态集中到设置，增加刷新及被拒绝后的系统设置入口。
- 待办编辑只负责日期、时间及是否启用；缺少权限时指向设置，不在多个编辑入口重复申请。
- 花园接入手机加速度计，增加有界弹性摇摆；仅待办页前台监听，离页／后台停止，无传感器保持静态，并尊重减少动态效果设置。
- 单项目筛选改为可搜索选择器，保留“全部项目”、单选及完成状态组合。
- 链接缩为紧凑卡片，域名与路径截断显示；纯链接消息不重复展示长网址，复制、编辑和导出仍保留完整 URL。

**状态：用户已确认 0.10.1 正常，该批已合入本地 main 并推送 GitHub。** 用户认可与执行者手机实测分别记录，不回填为所有设备条件均已测试。

## 0.11.0：逐条聊天、大正文与待办消息流

### 微信聊天逐条导入

- 区分 one by one 与 combine 的实际正文格式，从整篇长笔记改为按原发送动作生成独立消息。
- 发送者和原时间作为来源信息独立显示；同一个人连续发送、相同时间的消息不自动合并，单条正文内部换行不应误拆。
- 来源没有提供姓名或时间时明确显示未知，不猜测或伪造。
- 保留文字、内联图片及关联视频在原消息中的归属；未知结构需要确认原文回退。
- 原来源信息贯通编辑、搜索、跨项目转发、Markdown 和完整 JSON 备份恢复。

### 解除整份聊天五万字限制

- 移除整份聊天超过五万字即拒绝的限制，保留合理资源边界：正文 8MB UTF-8、最多 20000 条消息、单条文字上限 200 万字、图文 HTML 上限 1600 万字符。
- 正文及媒体通过原生桥接分块传输，预览分页，聊天初始及向前加载按批进行；长正文折叠显示，不把一条超长原消息伪装成多次发送。
- 导入保持原子事务，失败或取消不留下半批记录；备份校验及恢复同步兼容。
- 安卓单次整段复制另设 20 万字限制，可使用局部选择或导出。资源策略上限不代表已完成满上限真机性能测试。

### 真正的全屏输入

- 普通消息输入、待办输入的展开，改为复用现有笔记全屏编辑器，不再只是放大底部输入框。
- 已有待办编辑使用对应全屏界面；保留文字、图片、截止日期及提醒偏好。
- 共用草稿在展开／返回／切换中保持同步，返回不发送，确认不重复保存；底部发送不丢展开附件。
- 保留多行批量创建待办，每行一项，图片附于第一项；修正极短视口下按钮裁切。

### 待办像消息一样发送与转发

- 新旧待办直接融合进项目消息流，使用原任务 ID、创建时间及完成状态，不另外复制成第二份消息或任务，也不需要重新导入历史待办。
- 气泡可以点完成，文字加删除线；再次点击恢复未完成并去掉删除线。
- 气泡、项目待办栏、全局列表、花园及提醒状态保持同步，重开或恢复备份不重复生成任务。
- 待办可通过搜索／最近项目／多目标选择器转发到其他项目；目标仍是独立待办，默认未完成，原任务保留。
- 副本保留正文、独立附件、截止日期及未启用的提醒偏好，不自动创建或启用重复提醒；多目标失败整批回滚。
- 含视频的笔记转待办会明确拒绝，保留原笔记，不静默丢视频。

**状态：0.11.0 是历史候选版，后续改进已进入 0.12.0。该批业务尚未合并 main 或推送，不能把前批 0.10.1 的验收延伸到本版。**

## 0.12.0：通用文件、内层聊天与进一步交互修正

### 通用文件附件

- 聊天 ZIP 和普通系统分享支持 DOCX、PDF、PPTX、ZIP 及未知格式文件，不再仅因包含这些文件而拒绝整个聊天包。
- 用文件卡片保留文件名、类型、大小及原始字节，支持另存和调用外部应用打开。
- 外部应用获得对应临时文件的只读访问，排除自言自身，避免再次导入；没有可用应用时给出提示。
- 自言只保留／外部打开文件，不解析 Office／PDF 内容，不在 WebView 执行附件，不递归解压普通 ZIP 文件附件。
- 文件贯通原子转发、Markdown 附件导出及完整 JSON 恢复。

### 内层聊天与解析处理

- 识别明确缩进的内层聊天卡片，在导入预览和保存后的消息流中均可打开、分页查看。
- 保留内层来源、原时间、层级与图片／文件关联；转发时后代 ID 和媒体独立，导出及备份恢复保留层级。
- 对正文项目符号与逐条消息标记的歧义增加确认；未知嵌套结构保留原文，不强行制造消息边界。
- 明确嵌套深度上限为 8 层，总消息数包含内层；ZIP 单附件 200MB、解压总量 512MB、256 条目等资源限制继续保留。

**重要：解析已有改进，但用户实际使用仍发现问题，尚未解决。内层聊天“可以打开”已明确认可，不等于所有层级、消息边界或格式都解析正确。**

### 消息、待办与图文

- 待办气泡支持桌面双击及触摸双击进入全屏编辑；完成控件仅切换状态。
- 设置增加全局待办气泡显示开关，默认开启；关闭不删除任务，不影响待办栏和全局列表，重新开启可恢复显示。
- 移除消息流中普通消息及待办的三点按钮，保留长按菜单；其他列表菜单入口不扩改。
- 统一待办列表、气泡和全屏编辑的换行与行距，保留显式空行。
- 富文本草稿返回紧凑输入区后，从原全屏编辑器继续编辑，避免覆盖加粗和内联图片位置。
- 长图文增加只读完整查看，保留排版、图片、来源与附件，并可返回原页面。

### 花园运动

- 从简单弹性摇摆进一步增加盒内位移、速度、阻尼、边界及植物间碰撞。
- 保留前后台控制、无传感器降级和减少动态效果设置，不新增联网或传感器权限。

**状态：0.12.0 已本地提交、构建并经主对话核对。用户认可除微信导入解析外的本轮功能正常，内层聊天可打开；整批未验收通过，未合并或推送。**

## 数据、构建与项目整理

- 始终保持离线、无账号／云服务／统计；JSON 仍是包含附件和可编辑手写的完整恢复方式，Markdown 用于阅读及交换，不替代完整恢复。
- 沿用 `local.ziyan.notes` 和原升级签名；0.9.1 至 0.12.0 的 versionCode 依次为 11、12、13、14、15。
- SDK、JDK、Python、Node、Chrome、Playwright 位置及 PowerShell 命令统一记入 [工具链说明](TOOLCHAIN.md)，复用现有工具，不每次重新寻找。
- 补齐 [版本记录](CHANGELOG.md)、[当前状态](PROJECT_STATUS.md) 和分批任务／检查／交付／验收记录；私有签名、聊天样本、备份及安装包继续排除在 GitHub 之外。
- 明确同一任务的反馈由原负责人承接；开发交付后，主对话核对并在主对话提示验收，修复只复验修改及受影响范围。
- 明确整体验收通过后由原执行对话执行本地合并，主对话核对结果；推送、发布、删除分支和工作区分别授权。
- 通用协作提示词保留 V3.0 并生成 V4.0；固定执行模型为 GPT-6.1 Sol／中，本次独立产品分析指定 GPT-6 Astra／高。创建分析对话不计为产品功能完成。
